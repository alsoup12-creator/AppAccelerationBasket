应用加速箩筐 v0.1.1 · 应用库版

定位：

把需要使用代理线路的应用加入箩筐，再逐个选择、逐个启动。箩筐外应用保持直连。

当前支持：

1. Codex：普通启动走 Windows 应用入口；专用启动直接运行当前安装包内的程序，传入代理参数和代理环境变量，并检查主进程是否收到参数。登录和实际请求的线路仍需验证。
2. Chrome、Edge、Brave、Opera、Vivaldi：使用独立的加速浏览器配置目录，不影响普通浏览器窗口。
3. 其他应用：通过 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 环境变量进行通用尝试；应用如果不读取这些变量，就不会被真正加速。

使用：

1. 在“VPN 程序”区域选择 Veee，或添加并选择其他 VPN。
2. 点击“打开所选 VPN”；节点和智能/全局模式仍在 VPN 自己的界面操作。
3. 回到箩筐，在代理区域选择 Veee 或自定义 HTTP/SOCKS5，并测试线路。
4. 使用“添加 Codex”“已安装应用库”“桌面 / 文件”或“正在运行”加入箩筐。
   “已安装应用库”会扫描开始菜单、Windows 安装记录和 Microsoft Store 应用，并支持按名称搜索。
   “桌面 / 文件”会同时汇总个人桌面和公共桌面的应用快捷方式；也可以继续从其他文件夹选择。
5. 在列表中单击选择一个应用；底部两个启动按钮只作用于当前选中的这一项。
6. 对浏览器或通用应用尝试所选代理时，点击“专用加速启动选中应用”；对 Codex 点击“专用代理启动 Codex（验证参数）”。须先完全退出 Codex，再进行验证。
7. 需要跟随 Windows/VPN 当前网络模式时，点击“普通方式启动选中应用”。
8. 已经运行的非浏览器应用不会被重复启动，也不能中途切换线路；请先正常退出，等状态变为“未运行”后再选择启动方式。
9. 浏览器使用独立专用窗口；专用窗口已存在时，再点击会优先切回已有窗口。

首次登录：

- 普通桌面应用：如果首次登录或身份验证需要完整网络环境，可以先临时使用 VPN 的全局模式正常登录。登录完成后完全退出应用，再通过箩筐专用启动；多数应用会继续使用已经保存在本机的登录状态。
- Chrome、Edge 等浏览器：箩筐使用独立的浏览器配置目录，普通浏览器中的账号、Cookie 和扩展不会自动复制过来。首次使用时，应先启动 VPN，再从箩筐打开专用浏览器窗口，并在这个窗口里完成一次登录。
- 从箩筐专用浏览器内部新建的标签页或窗口，通常会继续使用专用线路；从桌面、任务栏或其他应用打开的普通浏览器窗口，继续使用原来的网络方式。

已安装应用库：

- “可验证代理启动 · Codex”：可以从箩筐启动 Codex 并检查主进程是否收到代理参数；收到参数也不等于登录和所有请求必然走代理。
- “已适配”：已支持的浏览器可以使用独立代理窗口。
- “通用尝试”：工具能找到明确的桌面程序，但应用是否读取代理参数仍需实际验证。
- “仅识别”：通常是 Microsoft Store 或系统应用，只有应用标识，没有可注入代理的桌面程序，因此显示为灰色且不能加入。
- Windows 系统工具、卸载程序和更新程序会尽量过滤，避免误加。
- “识别到应用”不等于“保证加速成功”；应用库只负责更方便、安全地找到启动入口。

VPN 程序区域：

- 这里只负责启动或切回 VPN 界面，不会替你切换节点、模式或连接状态。
- VPN 程序选择与代理线路配置相互独立。更换 VPN 后，需要确认下面填写的是新 VPN 提供的本地 HTTP/SOCKS5 地址和端口。
- Veee 安装在默认位置时会自动出现在选择框；其他 VPN 可以通过“添加其他 VPN”保存到列表。

状态说明：

- “普通方式运行中；不会重复启动”：本次由箩筐按普通方式启动，退出前不会再次发起启动。
- “专用启动中；代理效果待验证”：代理参数已经传给通用应用，但应用是否采用仍需实测。
- “正在运行；不会重复启动，退出后可切换”：工具确认程序已经运行；请退出后选择专用或普通方式重新启动。

防止重复启动：

- Codex 每次启动前都会重新识别当前安装版本，不再依赖保存的旧版本路径。普通启动使用 Windows 应用入口；专用代理启动需要直接运行安装包内的程序。如果 Windows 在更新期间拒绝该操作，箩筐会报错，不会把普通启动误报为加速。
- 安装位置暂时不可用时会短暂重查；Windows 临时拒绝启动时会重新定位当前版本并重试。若旧版 Codex 进程还在后台，箩筐会阻止再次启动。
- 启动过程中按钮会暂时锁定，连续点击不会重复执行。
- 箩筐本身只允许打开一个实例。

系统代理：

- 如果启动时 Windows 系统代理已开启，本工具会备份并关闭它，使箩筐外应用直连。
- “仅恢复 Windows 系统代理”只恢复系统设置，不会改变已经运行应用的线路。
- 如果系统代理原本已经由 Codex 专用工具关闭，本工具不会抢占或覆盖它的恢复备份。

限制：

- 初版不是 TUN/WFP 透明分流工具，未知应用不保证兼容。
- Windows 应用入口不会继承箩筐为单个进程设置的代理环境变量，因此专用模式使用直接进程启动；如果安装包不允许直接启动，该模式会失败。即使参数检查通过，代理线路和登录仍须实测。
- 如果未来 Codex 更新后彻底禁止直接进程启动，重试也不能解决，须改用新的进程级分流方案；箩筐会明确报错，不会把普通启动误报为专用加速。
- Codex 的 ChatGPT 登录会打开浏览器窗口；箩筐对 Codex 的进程代理设置不会自动传给另一个普通浏览器窗口。需要重新登录时，应单独确认浏览器的网络线路。
- 不能给已经运行的普通应用动态注入代理。
- 不支持要求用户名和密码的代理。
- 不强制结束任何应用。
- 不安装驱动、服务或浏览器扩展。

配置保存在：

%LOCALAPPDATA%\AppAccelerationBasket
